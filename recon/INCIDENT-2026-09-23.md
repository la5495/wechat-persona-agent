## 二、根因（Windows 事件日志，硬证据）

```
出错应用程序名称： Weixin.exe，版本： 4.1.15.9
出错模块名称：     frida-agent.dll          ← 就是它
异常代码：         0xc0000005   (ACCESS_VIOLATION)
错误偏移：         0x000000000009cbb5
出错进程 ID：      0x5188  = 20872  （我们 attach 的那个）
Faulting 模块路径： C:\Program Files\Frida\80f3ad38...\frida-agent.dll
```

**结论：崩的是 frida 自己的 agent，不是微信的数据、也不是微信的反注入。**
微信进程被 frida-agent 的访问违规带崩了。

## 三、触发点（按可能性排序，未 100% 钉死）

1. **无范围校验的内存读**：`safeStr()` 对 `args[0..3]` 直接 `readUtf8String(96)`。
   参数是**对象指针**（社区笔记也说过正文藏在 wrapper 里），不是字符串。
   对这种指针做字符串读，可能越过映射边界 → agent 内访问违规。
2. **`Thread.backtrace(this.context, Backtracer.FUZZY)`**：FUZZY 是启发式扫栈，
   在钩子回调里对任意线程上下文调用，本身就有出险记录。
3. **frida 17.18.0 agent 自身稳定性**：4 个钩子在**同一毫秒**同时进回调，
   agent 里的并发处理可能出问题。

**正确做法（下次如果要碰）**：
- 读之前先 `Process.findRangeByAddress(ptr)` / `Memory.query` 校验范围；
- 去掉 `Thread.backtrace`，或改 `Backtracer.ACCURATE` 且只在首个调用时取；
- 一次只挂**一个**钩子，观察一轮再挂下一个；
- 回调里把工作降到最小（只记指针值，不读内存）。
