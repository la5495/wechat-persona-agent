# 微信 AI 分身（WeChat Persona Agent）

> 读取你自己的微信聊天记录，蒸馏出**你的说话风格 + 长期记忆**，
> 然后让云端大模型**以你的身份**替你回复指定好友 —— 并且**绝不替你答应任何事**。

这是一个**个人向的工程实验**：把「阅读自己的聊天记录 → 量化风格 → 建人设与记忆库 →
用大模型模仿本人回话 → 通过 UI 自动化发出」这条链路完整跑通，并把踩过的坑都记下来。

⚠️ **先读 [风险与边界](#风险与边界) 再动手。** 这个项目会以**你的身份**对外说话。

## 它长什么样

```
微信本地库(SQLCipher)                 ┌── 读腿（只读解密副本，绝不写库）
      │                               │
      ├─ 密钥提取（扫进程内存）────────┤  wxsnap.py
      ├─ 解密 + WAL 合并 ────────────┤  增量刷新：每轮 <1 秒
      │                               └─ 会话/消息/联系人
      ▼
  语料管线（corpus/）
      ├─ export.py      导出范围内全部对话
      ├─ pairs.py       「对方说 X → 本人回 Y」样本 + 回复形态统计
      ├─ style_stats.py 风格量化（长度/标点/口头禅/连发分布）
      ├─ build_persona.py 人设包（**规则由统计机械生成**）
      └─ memory_build.py  长期记忆（L1 片段 + L2 事实，本地模型）
      ▼
  回复引擎（reply.py）
      ├─ 人设 + 联系人档案 + 检索记忆 + 真实例句 → 云端模型
      ├─ 红线过滤：不许约定 / 不许露 AI 身份 / 不许复读 / 不许编造
      └─ 连发多条 + 条数后处理
      ▼
  发送腿（sender/）                 ┌── 三道闸：空闲检测 / 前台还原 / 发后查库校验
      └─ UI 自动化（剪贴板 + 键盘）──┘
```

**控制分两层**（很容易搞混，但很重要）：

| 层 | 控制方式 | 作用 |
|---|---|---|
| 程序层 | `service.py start/stop` | 启动/退出后台常驻进程 |
| 回复层 | 微信给「文件传输助手」发 `开始`/`停止` | 进程照跑，只写草稿 ↔ 真发 切换 |

## 几个真正有用的设计（踩坑换来的）

### 1. 风格规则**必须由统计机械生成**，不能让模型写

实测本地 7B 模型会跟数据打架：明明语料里几乎不出现句号和感叹号，
它却写「标点使用较为频繁」。照它写的规则做出来完全不像。
→ 规则从数字里算，模型只负责定性的部分（联系人语域等）。

### 2. 风格靠**真实例句**传递，不靠形容词

「说话简短随意」这种描述没有信息量。直接给模型几条本人真实原话，效果立刻不同。

### 3. 「单条长度」≠「一轮长度」—— 最容易搞错的地方

同一个人，**单条消息**的平均字数，和**一轮回复**（连发多条合起来）的总字数，
是两个完全不同的量（作者的语料里差了将近一倍）。
早先只按"单条几个字"去约束，模型就只回两三个字，**一眼假**。

### 4. 用**盲测**量化「像不像」，而且必须防作弊

```
留出集（真实回复）→ 从人设例句中排除 → 让模型写同样场景 → 裁判分辨哪条是真人写的
```
**裁判正确率 ≈50% = 分不出来（成功）**。这个指标比"自己感觉像"可靠得多。
历史记录：72% → 50% → 44% → 78%（改坏了）→ 50%（最终）。

### 5. 红线要**确定性兜底**，不能只靠提示词

「不许替主人做约定」用三层防护：提示词 + 正则过滤（含上下文判定：对方在求助/借钱时
连回一个「行」都算答应）+ 生成后逐行拦截重写。

### 6. 发送**必须查库校验**

UI 自动化会**报成功但其实没发出去**。发完刷新副本、查库确认消息真的落库，
没落库就进重试队列。

## 快速开始

**环境要求**

| 需要 | 说明 |
|---|---|
| **Windows** | 项目依赖 Windows UI 自动化 + 微信客户端，macOS/Linux 跑不了 |
| **微信 4.x**（PC 版） | 已验证 **4.1.15.9**；其他版本库结构可能不同，先跑体检确认 |
| **Python 3.12** | 3.10+ 均可 |
| **Ollama**（可选） | 做记忆抽取与人设蒸馏；不装也能跑，只是这两步跳过 |
| **DeepSeek API key** | 回话用（也可改配置换别的兼容 OpenAI 协议的模型） |

**安装（5 步）**

```powershell
git clone https://github.com/<你的用户名>/wechat-persona-agent.git
cd wechat-persona-agent

# 1. 建虚拟环境 + 装依赖
uv venv .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.txt

# 2. 体检（会告诉你还缺什么、下一步做什么）
.venv\Scripts\python.exe doctor.py --fix

# 3. 按体检提示，把这几处填成你自己的：
#    config.json          → self_wxid（在 …\xwechat_files\<wxid>_xxxx\ 目录名里）
#    secrets.json         → DEEPSEEK_API_KEY
#    corpus/scope.json    → 要抓哪些会话（.venv\Scripts\python.exe wxsnap.py sessions 可查）
#    sender/config.json   → 发送腿白名单（默认只允许发「文件传输助手」，先拿它练手）

# 4. 解密微信库（**微信要开着**，密钥从它进程内存里读）
.venv\Scripts\python.exe wxsnap.py keys       # 只打印密钥指纹，不打印密钥
.venv\Scripts\python.exe wxsnap.py refresh

# 5. 蒸馏人设 + 建记忆（本地模型，零 API 费）
.venv\Scripts\python.exe corpus\export.py
.venv\Scripts\python.exe corpus\pairs.py
.venv\Scripts\python.exe corpus\style_stats.py
.venv\Scripts\python.exe corpus\build_persona.py
.venv\Scripts\python.exe corpus\memory_build.py
```

**先看它想说什么（不会发出去）**

```powershell
.venv\Scripts\python.exe run.py --once      # 只写草稿
type logs\drafts.jsonl                      # 看草稿
```

**满意了再启动常驻**

```powershell
.venv\Scripts\python.exe service.py start   # 启动（默认仍只写草稿）
# 然后在微信里给「文件传输助手」发「开始」→ 才真的会替你回话
# 想停：发「停止」；想彻底关：service.py stop（或双击 .cmd 按钮）
```

## 风险与边界

**这个项目会以你的身份对外说话**，请务必理解：

1. **只加你信得过、且知情的人进白名单**。朋友会把你「AI 说的话」当成你的真实意思。
2. **涉及钱、承诺、重要安排的话，自己说**。项目虽然用三层防护禁止 AI 替你答应任何事，
   但**不保证 100%**，最终责任在操作者。
3. **不要用它冒充他人**（读取别人的聊天记录、冒充别人身份）—— 这个项目的前提是
   **读自己的号、以自己的身份、回自己的好友**。
4. **微信使用条款**：客户端自动化与数据库读取可能违反腾讯的服务条款，账号存在风险，
   请自行评估。**本项目仅供个人学习研究。**
5. **隐私**：解密副本、密钥、语料、记忆库全是敏感数据，`.gitignore` 已默认排除，
   **绝不要提交到公开仓库**。

## 目录结构

```
├── doctor.py           🩺 环境体检：拿到项目先跑这个
├── wxsnap.py           读腿：密钥提取 / 解密 / 会话消息 / 版本兼容检查
├── run.py              编排：判定该回谁 → 生成 → 连发 → 查库校验
├── reply.py            回复引擎：人设提示词 + 四道红线过滤
├── guard.py            闸门：白名单 / 速率 / 脱敏 / 约定红线 / 人设泄露
├── persona.py          人设加载
├── service.py          程序开关：start / stop / status / health / logs
├── update.py           日常更新：语料 + 记忆 + 健康 + 兼容，一条命令
├── switch.py           回复层开关（命令行版）
├── whitelist.py        白名单管理
├── sender/             UI 发送腿（自带 wxcore）
├── corpus/             语料与人设管线（详见 corpus/README.md）
└── docs/               设计与踩坑记录
```
