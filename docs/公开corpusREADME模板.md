# 语料与人设管线

这一层把**你自己的微信聊天记录**变成「说话风格 + 长期记忆」。

> 本目录里的每个脚本都是**通用**的：读的是你本机的库，产出的是你自己的人设包。
> 仓库里**不含任何人的**聊天语料、风格统计或记忆库 —— 那些都在 `.gitignore` 里。

---

## 流程

```
export.py        →  turns/<会话>.jsonl    范围内会话的全部对话（原样保留，含表情与单字）
pairs.py         →  pairs.jsonl           「对方说 X → 本人回 Y」样本
style_stats.py   →  style_stats.json      风格量化（长度 / 标点 / 口头禅 / 连发分布）
distill.py       →  profiles/<会话>.md    每个联系人的语域档案（本地模型写）
build_persona.py →  persona/              人设包：确定性规则 + 精选例句 + 联系人档案
memory_build.py  →  memory.db             L1 片段 + L2 事实（本地模型抽取，可断点续跑）
memory_merge.py  →                        把小而相邻的片段合并，减少碎片
memory_tidy.py   →                        去重 + 清过期事实（每周跑一次）
```

跑完这一套，`run.py` 才有东西可用 —— **没跑之前它不会回任何消息**（会提示「人设包不完整」）。

## 三条设计原则（都是踩坑换来的）

### 1. 风格规则必须**由统计机械生成**，不能让模型写

拿本地小模型去总结风格，它会写出与数据矛盾的话（例如数据里几乎没有句号，
它却写「标点使用较为频繁」）。照这种规则做出来完全不像本人。

→ **规则从数字里算**（`build_persona.py`），模型只负责定性的部分（联系人语域）。

### 2. 风格靠**真实例句**传递，不靠形容词

「说话简短随意」这种描述没有信息量。直接给模型几条**本人真实原话**，
效果立刻不同。所以 `examples.jsonl` 必须原样引用，不能改写。

### 3. 「单条长度」≠「一轮长度」

本人**单条消息**的平均字数，和**一轮回复**（连发多条合起来）的字数，
是两个不同的量。只按单条长度去约束，模型会只回两三个字 —— 一眼假。
两个都要算，并且按「对方说了多少」动态调整。

## 记忆库（`memory.db`）

一个 SQLite 文件，两张主表：

| 表 | 内容 | 用途 |
|---|---|---|
| `episode` | 对话片段摘要（谁、什么时候、聊了什么） | 检索"上次聊到哪" |
| `fact` | 长期事实（关系、偏好、常提的事） | 检索"关于他我知道什么" |

配 FTS5 全文索引，检索走 **bigram 重合 + 同会话加分 + 时间新鲜度**，
其中**临时事实**（含「明天/这周」这类词）会快速衰减 —— 否则模型会拿
一个月前的「明天要交作业」当成现在的事。

---

## 抓取范围（`scope.json`）

```json
{ "since": "2026-07-01", "chats": ["好友A", "某个群"] }
```

- `since`：只抓这个日期之后的
- `chats`：会话名要和微信里显示的**完全一致**（`python wxsnap.py sessions` 可以查）

从示例开始：
```powershell
copy corpus\scope.example.json corpus\scope.json
```

## 本地模型

`distill.py` / `memory_build.py` 用 **Ollama**（默认 `qwen2.5:7b`）做抽取，**零 API 费**。
没装 Ollama 也能跑主流程，只是这两步做不了（人设包会缺联系人档案、记忆库为空）。
