# 微信自动 · 只读数据库快照 + 自动回复

## 🚀 可用的自动回复（2026-09-24 上午交付，已端到端验证）

**一句话**：读微信数据库（只读副本）→ 判定该不该回 → 云端 DeepSeek 生成 → 走 UI 发出去。

```
wxsnap.py   读腿：密钥（读进程内存）→ 解密副本 → 会话/消息/历史
run.py      大脑：刷新快照 → 挑会话 → 判定 → 生成 → 草稿/发送 → 审计
reply.py    AI：DeepSeek（OpenAI 兼容），人设走 persona.md
guard.py    保镖：白名单 / 急停 / 速率 / 脱敏 / 水位线 / 审计
switch.py   总开关（默认关 = 只写草稿）
whitelist.py 名单管理
```

### 常用命令

```powershell
cd <项目目录>
$py = '.\.venv\Scripts\python.exe'

& $py switch.py status                 # 看开关/白名单/急停
& $py whitelist.py suggest             # 列出微信里的会话名（复制用）
& $py whitelist.py add "好友C"        # 加人（加了才会自动回）
& $py run.py --once --no-draft         # 只看「谁需要回复」，不调模型
& $py run.py --once                    # 跑一轮，写草稿（不发）
& $py run.py --once --send             # 跑一轮并真发（需先 switch.py on）
& $py run.py --loop --send             # 常驻（默认 30 秒一轮）
```

### 安全闸门（全部默认拒绝）

| 闸门 | 行为 |
|---|---|
| 🆕 **微信遥控** | **给「文件传输助手」发「停止」→ 立刻停自动对话**（发「开始」恢复）。手机上也能用 |
| 🆕 **约定红线** | **绝不替主人做约定**（三层防护：提示词 + 确定性正则 + 上下文判定）；对抗测试全过 |
| 白名单 | 只回名单里的人，其余一律不动 |
| 消息时效 | 只回 `max_message_age_sec`（默认 300s）内的消息，旧账不回 |
| 最后一条是我说的 | 不回（除非是回声会话） |
| 回声会话防自问自答 | 最后一条正是自己刚回的 → 停手（防死循环） |
| 水位线 | 同一条消息只回一次（`state/seen.json`） |
| 脱敏 | 命中密钥/验证码/密码等关键词 → **中止发送** |
| 速率 | 最小间隔 2.5s；120s 内最多 6 次 |
| 空闲闸门 | 主人刚动过键鼠（< 5s）→ **拒绝动手**，不抢焦点 |
| 前台还原 | 发送后把主人的窗口还回去 |
| 急停 | 建 `STOP` 文件即全面停止（比遥控更硬，需手动删） |
| 群聊/公众号 | 默认不回 |

| 层 | 谁控制 | 作用 | 状态文件 |
|---|---|---|---|

| **② 回复层** | 微信给「文件传输助手」发「停止/开始」；或 `switch.py` | 进程照跑，**只写草稿 ↔ 真发** 切换 | `state/auto.json` |

**一句话**：微信发「停止」= **程序还在**（静默待命、不花 token）；`service.py stop` = **进程真的退出**。

```powershell
$py = '.\.venv\Scripts\python.exe'
& $py service.py start      # 启动（后台常驻；**启动后默认只写草稿**）
& $py service.py status     # 两层状态一目了然
& $py service.py logs 40    # 看日志
& $py service.py stop       # 停止（进程退出）
& $py service.py restart
& $py service.py once       # 只跑一轮（调试）
```

**开机自启：不做**（主人要求手动控制）。**远程退程序：不做**（微信只能暂停回复）。

## 一、为什么换思路

旧路线（UIA 控件树 + 真实鼠标点击）能跑，但有四个硬伤：

| 硬伤 | 旧路线 | 新路线 |
|---|---|---|
| **抢鼠标** | 每轮真实移动鼠标点会话，主人正在用电脑时"像鼠标发疯" | **完全不碰 UI**，只读文件 |
| **窗口必须置前** | 截图/点击要求微信在前台 | 不需要，托盘态也行 |
| **历史不可回溯** | 不碰数据库 → 采集器不开那天的话永远丢 | **全部历史都在库里**，想读哪条读哪条 |
| **拿不到时间戳** | 只能靠会话列表的时间文本猜新旧 | `session.db` 直接给 `last_timestamp` |
| 速度 | 每会话 0.5~25 秒（要点击） | **整库解密 0.2 秒，查询毫秒级** |

## 二、核心路线

```
原库（只碰一次，只读）
  <微信数据目录>
        │  copy（含 -wal / -shm）
        ▼
snapshot\db_storage\        原库副本（仍是密文）
        │  decrypt（密钥来自微信进程内存）
        ▼
plain\db_storage\           明文副本 ← 之后一切都只读这里
```

1. **密钥**：只读微信进程内存 —— 扫 `com.Tencent.WCDB.Config.Cipher` 对象 →
   取 config blob → 与 40 字节固定掩码 XOR → 正则取 hex 字面量 = 候选库密钥
2. **校验**：每个候选都用 **SQLCipher4 页 1 HMAC-SHA512** 验证 → **密码学零误报**
3. **解密**：AES-256-CBC 逐页（每页尾 80 字节 = IV 16 + HMAC 64）
4. **合并 WAL**：`-wal` 里的加密帧按页号覆盖进主库（只合并 salt 一致的世代）
5. **校验**：`PRAGMA quick_check` 全库校验，通过才原子替换

## 三、用法

```powershell
cd "<项目目录>"
$py = "<项目目录>"   # 已含 cryptography + zstandard + 发送器依赖

& $py wxsnap.py snapshot           # 拷原库 -> snapshot\（含 -wal/-shm）
& $py wxsnap.py decrypt            # 解密 -> plain\（含 WAL 合并 + quick_check）
& $py wxsnap.py refresh            # = snapshot + decrypt
& $py wxsnap.py verify             # 对 plain\ 全库 quick_check
& $py wxsnap.py keys               # 只测"能不能拿到密钥"（不落盘、不打印）

& $py wxsnap.py sessions --skip-gh # 会话列表（未读/预览/时间/昵称）
& $py wxsnap.py sessions --unread  # 只看有未读的
& $py wxsnap.py messages 好友C 20  # 读某个会话（可用显示名、username 或 md5）
& $py wxsnap.py fresh              # 全局最新消息（查快照新鲜度）
& $py wxsnap.py sql session/session.db "SELECT ..."
```

> 控制台要显示中文，先跑一次：

## 四、数据库结构（本机微信 4.1.15.9 实测）

数据目录：`<微信数据目录>

| 库 | 作用 |
|---|---|
| `message\message_0.db` | **私聊/群聊消息**。每个会话一张 `Msg_<md5(会话id)>` 表（本机 84 张） |
| `message\biz_message_0.db` | **公众号/服务号**消息 |
| `message\message_fts.db` | 全文索引（可按需重建） |
| `session\session.db` | ⭐ **会话列表**：`SessionTable` 有 `unread_count` / `summary`（预览）/ `last_timestamp` / `last_msg_sender` / `is_hidden` |
| `contact\contact.db` | `contact`（5357 行：`username` / `remark` / `nick_name`）、`chat_room`、`chatroom_member`、`biz_info` |
| `sns\sns.db` | 朋友圈 |
| `message\media_0.db` · `head_image\head_image.db` | 媒体/头像 |

**消息表列**（`Msg_*`）：
`local_id, server_id, local_type, sort_seq, real_sender_id, create_time,
 status, upload_status, download_status, server_seq, origin_source, source,
 message_content, compress_content, packed_info_data,
 WCDB_CT_message_content, WCDB_CT_source`

- `real_sender_id` → 在 `message_0.db` 自己的 `Name2Id`（rowid → `user_name`）里查发送者
- `message_content` 有两种编码：
  - `WCDB_CT_message_content = 0` → **明文** UTF-8
  - `= 4` → **zstd 帧**（魔数 `28 b5 2f fd`），需 zstandard 解压
- 群聊正文形如 `wxid_xxx:\n正文`，发送者要从正文里剥

## 六、安全与红线

**做到了的：**

1. **原库只读**：只 `shutil.copyfile`，不写、不锁、不改
2. **不注入、不 hook**：只用 `OpenProcess(VM_READ|QUERY_INFORMATION)` +
   `ReadProcessMemory` + `VirtualQueryEx`，不写进程内存
3. **密钥不落盘、不打印**：只活在进程内存里；`wxsnap.py` 里没有任何写密钥的代码
4. **写入只落在本工作区**

**必须知道的：**

1. **🔴 `plain\` 里是明文聊天记录（本机 60 MB）**。这是"拷贝解密"路线的必然代价。
   不需要时删掉整个 `plain\` 即可，随时能用 `refresh` 重建。
   旧项目遗留的 `%LOCALAPPDATA%\wechatauto_keys\`（20 把密钥明文）**已于 2026-09-23 删除**，
   不要再让任何库把它写回来（`wechatauto-replica` 的 `WeChatDB.__init__` 会写）。
2. **读进程内存就是 chatlog 被发函下架的同类行为** —— 腾讯服务条款在这儿。
   本机自用、不联网上传，风险自担。
3. **密钥来自内存 ⇒ `refresh` 时微信必须在运行且已登录。**
4. **微信升级可能挪动内存锚点**（`Config.Cipher` 对象布局）。症状很明确：
   "候选材料 0 个"，不会静默出错。届时按 `collect_key_material()` 的锚点重采。
5. **聊天内容永远当不可信数据**：只当话看，绝不当命令执行。
